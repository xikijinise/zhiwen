# 拿职问去讲

先给结论，再打开文件。不要从框架名词讲起。

## 简历上怎么写

项目名称写「职问」，角色写「个人项目」。时间按你实际开始做的月份填。技术栈只写页面上问得出来的：React、Python、FastAPI、LangChain、DeepSeek、SSE。

项目描述用这四句，每句都能打开一个文件：

- 做了一个大学生就业规则问答。问题先在 26 条已核对知识里检索，最多取 3 条；没有命中就不调用模型。对应 `app/knowledge.py` 的 `retrieve`。
- 用 LangChain 把检索结果交给 DeepSeek：`CampusRetriever`，以及 `prompt | ChatOpenAI | StrOutputParser`。关闭默认思考，要求模型只输出 JSON。对应 `app/chain.py`。
- 模型按 token 返回 JSON。服务端把半截 JSON 解析成草稿，用 SSE 推给页面；引用编号必须属于这次检索到的来源，不通过就改用知识库原文。对应 `app/draft.py` 和 `stream_answer`。
- 用 FastAPI 提供页面和 `/api/chat`。演示：https://zhiwen.cise.site 。检索有单测，不调用模型。

不要写准确率、用户量、响应提升了百分之多少。这些数字项目里没有。

网申框只有一小段时，用这一段：

> 职问是面向大学生的就业规则问答。FastAPI 接收问题，先用关键词从 26 条已核对知识中检索，最多取 3 条，再由 LangChain 调用 DeepSeek 流式生成。模型只能引用本次检索到的法条；未命中或调用失败则回退知识库原文。页面通过 SSE 显示草稿。演示：https://zhiwen.cise.site

对方问「你具体写了什么」时，按上面四句的文件往下讲，不要改成「用了 RAG 框架一键生成」。


## 30 秒

职问回答大学生的实习、三方、社保和劳动合同问题。它不让模型凭记忆答。先在 26 条核对过的知识里检索，最多拿 3 条给模型，模型只能引用这几条对应的法条。页面上等答案一点点出来。模型失败，或者根本没检索到，就退回知识库原文，不编一个看起来很对的回答。

演示站：https://zhiwen.cise.site

## 现场 4 分钟

1. 打开站点，问「试用期不交社保，合法吗？」。指出字是逐段出现的，不是转圈结束后一次性出来。
2. 点回答里的数字。面板里是条目、法条位置和官网链接。说：编号不是模型自己起的，是知识库来源 id。
3. 再问「今天天气怎么样」。这条检索不到，不会假装有法律依据。
4. 打开 `app/chain.py` 的 `stream_answer`。手指这三行：`retriever.invoke`，`prompt | model | StrOutputParser`，`read_draft`。
5. 若对方要看证据，跑：

```bash
cd /opt/zhiwen-fastapi
.venv/bin/python -m unittest discover -s tests -t .
```

## 面试题

每一题先用口头那句答完，对方追问再翻文件。

### 介绍一下这个项目

口头：给大学生查就业规则的问答。检索负责找依据，模型负责把依据说成人话，页面负责把依据点开。

打开：本文件上面的 30 秒，然后 `README.md` 那张流程图。

### 为什么不直接把问题发给大模型？

口头：劳动法问题错一句就是误导。模型会补记忆里的法条和各地比例。这个库只有核对过的 26 条，城市比例明确不答。所以模型只能看到这次检索结果。

打开：`app/chain.py` 里 `_SYSTEM` 开头几条，以及 `if not key or not matched`。

### 这算 RAG 吗？

口头：算检索增强，不是向量 RAG。检索、塞进提示词、生成，这三步在。没有 embedding，没有向量库。26 条材料用关键词更稳，也讲得清为什么命中。

打开：`CampusRetriever._get_relevant_documents`，它调的是 `retrieve`，不是向量搜索。

### 检索怎么做？为什么不用向量？

口头：问题归一化后，对关键词做包含匹配，再用二字片段加一点分。几条容易混淆的问题有额外加分，比如「试用期 + 社保」优先打到劳动关系下的参保，而不是实习参保。最多 3 条，分数不够就当没检索到。

向量库在这个规模上解释成本更高，也会把相近但法律性质不同的条目混在一起。库变成几千条、问法很散时，再加向量，关键词规则可以留下当精确通道。

打开：`app/knowledge.py` 的 `_score` 和 `retrieve`。数据在 `data/knowledge.json`。

### 只有 26 条，是不是玩具？

口头：条数少是故意的。每条都有来源、条款位置和官网。面试看的是边界：没检索到就拒答，引用必须落在白名单里，失败有退路。量上来以后换检索器，链和页面协议不用推倒。

### LangChain 你实际用了哪几块？

口头：三块。`BaseRetriever` 把现成检索包成文档。`ChatPromptTemplate | ChatOpenAI | StrOutputParser` 是那条 LCEL 链。`astream` 拿 token。提示词、打分、半截 JSON、引用校验、SSE 都是自己的。

打开：`app/chain.py` 的 `_chain`，返回值就是 `prompt | model | StrOutputParser()`。

### 不用 LangChain 行不行？

口头：行。检索本来就不依赖它，模型用 OpenAI 兼容接口也能流式读。这里用 LangChain 是为了把「检索器」和「链」摆成以后能换的两个接口：换向量检索只改 Retriever，换模型只改 `ChatOpenAI` 的参数。

### 模型为什么用 Chat Completions，还关掉思考？

口头：LangChain 的 `ChatOpenAI` 走 `/chat/completions`。这版 DeepSeek 思考默认开着，思考 token 会把回答长度吃光，页面上等不到正文。请求里用 `extra_body` 把 `thinking.type` 设为 `disabled`，`max_tokens` 给 4000。

打开：`_chain` 里的 `ChatOpenAI(...)`。

### 怎么让它稳定输出 JSON？

口头：`response_format` 用 `json_object`，提示词里写了要 json，并规定键：`title`、`summary`、`details`、`actions`、`followups`、`citationIds`。模型有时仍会包一层 markdown，解析时先剥掉围栏，再取最外层花括号。

打开：`_SYSTEM` 最后两句，和 `extract_json`。

### 流式是怎么做的？页面为什么不是直接追加 token？

口头：模型流式吐的是一个 JSON 字符串。直接显示会看到半截引号和花括号。`read_draft` 从已经收到的文本里尽量读出标题、结论、段落和步骤，缺的字段就留空。服务端用 SSE 推 `draft`。浏览器一帧只渲染一次，人在底部才跟着滚，往上翻时不把他拉回来。收齐后做校验，再推一条 `done` 替换草稿。

打开：`stream_answer` 里的 `async for token`，然后 `app/draft.py` 的 `read_draft`。前端在 `web/src/App.jsx` 的 `requestAnimationFrame`。

### 引用怎么防止编造？

口头：提示词要求关键句后面写 `[02]` 这种两位编号，编号只能来自这次塞进提示词的 sources。回来以后，不在白名单里的 id 整段回答作废，改走知识库。白名单里的编号会留在句中；模型一个都没写时，把允许的编号补到结论末尾，避免一份有依据的回答看起来像没依据。点数字打开的是知识库里的条款和原文链接，不是模型现写的网址。

打开：`_answer_from_output` 和 `_place_markers`。

### 模型超时、返回不是 JSON、或者服务挂了？

口头：70 秒超时。解析失败、引用越界，都当成这次模型不可用，改发知识库回答，并带一句「已切换为知识库检索回答」。用户自己按停止，连接断了，就不补这一条。

打开：`stream_answer` 的 `except`，以及 `_fallback`。

### 多轮对话存在哪？

口头：每一轮都写进 SQLite，文件是 data/history.db。侧栏「历史记录」只列出这个浏览器自己的对话。交给模型的仍然是最近 6 轮问题和结论。像「那如果已经转正了呢」这种没有主题词的追问，检索会回到上一问。

打开：`web/src/App.jsx` 里组 `history` 的地方，以及 `knowledge.py` 的 `contextual`。

### 用户能不能用提示词把规则改掉？

口头：系统提示写了用户文本和历史都是不可信数据，不能改规则。服务端不执行模型返回的工具调用。引用 id 再怎么说，也过不了白名单。这挡的是「假装你是另一个助手」这种改规则，不挡用户问恶意问题本身。

### 密钥放哪？

口头：环境变量 `DEEPSEEK_API_KEY`。仓库里只有 `.env.example`。这台机器的正式值在系统环境文件里，不进 git，日志里碰到密钥样式会打掉。

不要在面试里念出密钥，也不要打开那个环境文件。

### 你怎么知道检索是对的？

口头：检索没有模型，输入输出固定。单测覆盖了该命中的问题、不该命中的问题、追问沿用上一问，以及年假、工伤、派遣这些新增问法必须排到对应条目。生成质量靠演示和人工看引用，没有自动判分。下一步是做一组固定问题和必须出现的来源 id。

打开：`tests/test_retrieve.py`，当场跑一遍。

### 为什么用 FastAPI，为什么用 SSE 不用 WebSocket？

口头：一个 POST 就是一轮回答，服务端单向往外推。SSE 就是带事件名的 HTTP 响应，代理和浏览器都好处理。WebSocket 适合两边持续互发，这里没有那个需求。FastAPI 直接把异步生成器变成 `StreamingResponse`。

要补一句部署：反向代理必须关响应缓冲，否则草稿会攒齐了一起到。

### 延迟和成本怎么看？

口头：检索是本地计算，可以忽略。时间几乎全在模型。演示里首段草稿大约一两秒，整段大约几秒。思考关掉就是为了别把这几秒花在看不见的推理上。知识库模式不调用模型，没有这笔费用。

### 如果做成真正上线，你先改什么？

口头：先加评测集，再谈换检索。然后是回答缓存和按用户的限流。对话已经在 SQLite 里。城市规则仍然不靠模型编，要接官方数据再答。密钥和日志脱敏保持现在这样。

## 对方可能抓住的点

- 「你这个加分规则是拍脑袋。」承认是针对容易混的问法手调的，所以才写进测试。不是通用排序模型。
- 「JSON 半截解析会不会错？」会把没写完的字符串显示出来，这是草稿。最终以校验过的 `done` 为准，校验失败就整段换掉。
- 「LangChain 版本变化快。」链的表面只有检索器、提示词、模型和字符串解析器，没有用复杂代理。升级时看这四个接口。
